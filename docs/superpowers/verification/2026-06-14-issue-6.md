## Implementation Summary

### Root Cause Analysis
The original issue was that the floating toolbar would appear briefly even when no text was selected. This occurred because:
1. The clipboard fallback had no way to distinguish between a successful copy (Ctrl+C) and a timeout
2. Old clipboard content could be mistakenly treated as "selected text"
3. Pending toolbar state was shown before text capture was confirmed

### Solution: Sentinel-Based Clipboard Detection

**Key Changes:**

1. **Sentinel-based clipboard capture** (`src/main/text-capture.js`)
   - Write a unique sentinel value to clipboard before simulating Ctrl+C
   - After waiting, compare clipboard content with sentinel:
     - If unchanged: No selection was copied (timeout/empty) → return empty string
     - If changed: Selection was copied → return trimmed text
   - Always restore original clipboard content after capture

2. **Defensive check in showWindow** (`src/main/floating-window.js`)
   - Added `normalizedText = String(text || '').trim(); if (!normalizedText) return false;`
   - Provides belt-and-suspenders protection against empty text

3. **Toolbar gate helper** (`src/main/text-capture.js`)
   - `shouldShowToolbarForCapturedText(text)` returns true only for non-empty trimmed text
   - Called before invoking `onTextCaptured` callback

4. **Removed pending session logic**
   - Eliminated `showPendingWindow`/`hidePendingWindow` code paths
   - Toolbar is shown only after text capture is confirmed non-empty
